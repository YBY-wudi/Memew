# 知识点扩写规范（5 本自编教材共用）

> 所有扩写任务都必须严格遵守本文件。字段名、层级、口诀和类比的写法都在这里定死。

## 一、文件位置与导出

每本书一个文件，位于 `D:/memorize/memorize-miniprogram/miniprogram/data/ai-books/<id>.js`：

| 文件 | 书 id | 学科 |
|---|---|---|
| `cell-biology.js` | `cell-bio-01` | 生物学（大学） |
| `high-chemistry.js` | `high-chem-01` | 化学（高中） |
| `elementary-math.js` | `elem-math-01` | 数学（初等） |
| `civil-service.js` | `civil-serv-01` | 常识判断（公考） |
| `cet4-vocabulary.js` | `cet4-vocab-01` | 英语（四级） |

导出形式：`module.exports = [ 整本书对象, ... ]`（数组，每本书一个对象）。

## 二、层级结构

module.exports = [

## 三、知识点字段（**字段名不能改**）

```js
{
  title: '细胞学说',            // 必填，短标题，≤14 字
  index: '细胞学说',            // 选填，显式索引词；不给就自动提取
  content: '正文……',            // 必填，≥180 字，是背诵/遮挡/默写的唯一文本源
  keywords: ['施莱登', '施旺'],  // 必填，4-8 个，遮挡位就落在这里
  aids: {
    // ↓↓↓ 以下 6 个是零额度必填，缺一个 check-ai-books 就报错
    core:       '一句话核心',
    chain:      'A → B → C → D',
    structure:  '①…… ②…… ③……',
    contrast:   '与 X 的区别在于……',
    qa:         '问：……？答：……',
    scene:      '想象你在……',
    // ↓↓↓ 以下 3 个是加分项，强烈建议写满
    mnemonic:   '押韵口诀',
    analogy:    '生活化类比（含逐条映射 + 失效点）',
    exam:       '考点提示，写清常考角度'   // 必填
  }
}
```

**注意**：`mnemonic` / `analogy` / `exam` **三个都在 `aids` 对象里面**，`aids` 外面没有 `exam` 字段（和现有 7 本文件一致，不要放错层级）。

⚠️ 这行以前写的是「`exam` 在 `aids` 外面」，是**错的**——实测 `cell-biology.js` 等 7 本现有教材的 `aids` 键都是 `core/chain/structure/contrast/qa/scene/mnemonic/analogy/exam` 九个，`p.exam` 全部不存在。照错的地方写会让 `check-ai-books.js` 误判，也和新教材不一致。

## 四、正文 content 的写法

- ≥180 字，目标是 **220-320 字**，宁可长不要短（用户明确要求「知识点扩充确实要详细」）
- 必须包含：定义/机制 + 具体数值或条件 + 易错边界
- 教材原话式的准确表述，不要口语化水分
- 句子之间用中文全角标点；JS 字符串用**单引号**并用 `+` 拼接多行（保持与现有文件一致的风格）

## 五、口诀 mnemonic（用户点名的特色，必须写好）

- **7-14 字**，押韵，尽量两行（用 `\n` 分隔）
- **每个字都要对应真实信息**，不许有纯凑字数的字
- 优先搜「已公认的口诀」，没有就自编并保证押韵
- 好的例子：
  - `'酶温两重天：\n高温变性不可逆，低温只是暂休息'`
  - `'氧化还原得失电子：\n升失氧、降得还'`

## 六、类比 analogy（用户点名的核心特色，质量红线）

必须写满 4 件事，缺一不可：

1. **逐条映射**：明确写出「知识点要素A ↔ 类比物要素B」，不能只说「它们很像」
2. **对比结构**：知识点里若有两个相反/并列现象（高温vs低温、有性vs无性、主动vs被动），类比必须两个都覆盖，形成对照
3. **生活细节**：具体到动作和现象（煮鸡蛋、腌咸菜、吹气球、堵车），不能停留在「加热」「改变」这类抽象词
4. **失效点**：最后必须写明「这个类比在哪不适用」

**反面示例（禁止）**：
> ❌ `'细胞膜像守卫一样把守物质进出'` —— 没有映射，没有细节，没有失效点

**正面示例（照这个写）**：
> ✅ `'煮鸡蛋 ↔ 酶变性：低温只是让分子运动变慢（分子结构没变，升温就恢复）；高温把肽键的氢键二硫键破坏，空间结构崩解成固状物（再降温也回不到生液态）。失效点：低温下酶的活性中心并未被破坏，千万别记成「低温使酶失活」。'`

## 七、易混辨析 contrast

不要写「A 和 B 不同」这种废话。要写成：
`'A 像 B，但差在……；抓住「一个区别点」就够'`

## 八、自问自答 qa

- 问的部分要能引出**原理**，不是问定义
- 答的部分 40-80 字，说清为什么
- 一条知识点只写一组问答

## 九、场景挂钩 scene

用第二人称想象画面，带具体动作和感官细节（看到什么、听到什么、手上在做什么）。
不要写「在实验室里」这种空场景。

## 十、完成后必须自检

在项目根目录 `D:/memorize/memorize-miniprogram` 跑：

```bash
node tools/check-ai-books.js
```

必须看到「✅ 字段完整性全部通过」和「失败 0 项」。若报错，按提示补齐字段后重跑。

**注意**：`check-ai-books.js` 会检查全部 5 本书。如果你只改了 1 本，其他 4 本的报错不是你的问题（但如果原本是全绿，说明是你改坏的）。

另外 `miniprogram/data/ai-books/` 和 `database/ai-books/` 是同一份内容的两份副本，**改完 miniprogram 那份后必须把改动同步到 database 那份**，否则 `tools/test-local-books.js` 第 6 项会报副本漂移。同步方式：直接用相同内容覆盖对应文件。

## 十一、绝对不要做的事

- 不要改 `miniprogram/utils/` 下的任何工具文件
- 不要改 `miniprogram/app.json`
- 不要改已有知识点的 `title`（会破坏既有索引和分享链接）
- 不要动 `tools/` 下的脚本
- 不要写 `Math.` / `JSON.` 之类到 WXML（本任务不碰 WXML）
- 改完不要新增 `miniprogramRoot` 之外的文件依赖
